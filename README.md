# Harmony VPN — полный бриф для продолжения разработки

Это единый документ с контекстом и задачами на все три фазы. Дальше весь проект
ведётся здесь, в Claude Code — просто иди по фазам по порядку, не перескакивая,
т.к. каждая следующая опирается на модели/код из предыдущей.

## Контекст проекта

Harmony — сервис продажи VPN-подписок (VLESS Reality) через Telegram-бота.
Архитектура:
- **Marzban** (отдельный сервис, ставится по официальной инструкции Gozargah/Marzban) —
  реально управляет Xray-нodами, отдаёт subscription-ссылки. Harmony обращается к нему
  только через REST API, никогда не трогает Xray напрямую.
- **Harmony bot** (этот репозиторий) — Telegram-бот на aiogram 3.x + своя БД
  (SQLAlchemy, сейчас SQLite, для прода — Postgres) для тарифов/заказов/рефералки/тикетов.
- Стек: Python 3.12, aiogram, httpx, SQLAlchemy (async), три платёжных провайдера
  за общим интерфейсом (`payments/base.py`): ЮKassa, CryptoBot, Telegram Stars.

Уже реализовано и проверено на синтаксис (но не разворачивалось вживую):
- `marzban_client/client.py` — полный клиент Marzban API
- `payments/` — три провайдера
- `db/models.py` — User, Tariff, Order, PromoCode, SupportTicket, TicketMessage
- `bot/handlers/{start,tariffs,payment}.py` — сценарий `/start` → `/buy` → оплата → выдача
- `bot/services/delivery.py` — общая логика выдачи доступа после оплаты

**Важное правило: не переписывай архитектуру этих файлов без необходимости.** Модели
в `db/models.py` уже спроектированы с учётом Фаз 2-3 — расширяй их, а не переделывай.

## Quick Start

### Вариант 1 — Docker Compose (рекомендуется)

Поднимает бот + Postgres. Marzban должен быть развёрнут отдельно заранее
(см. [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) — полный чек-лист с нуля).

```bash
cp .env.example .env
nano .env   # заполни BOT_TOKEN, MARZBAN_URL и т.д. — см. docs/CONFIGURATION.md
docker compose up -d --build
docker compose exec bot python seed_tariffs.py
```

Готово — пиши `/start` боту в Telegram.

### Вариант 2 — вручную (для разработки)

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
nano .env   # DATABASE_URL можно оставить sqlite для локальной разработки

python seed_tariffs.py
python -m bot.main
```

Подробности по каждой переменной `.env` — [docs/CONFIGURATION.md](docs/CONFIGURATION.md).
Полный чек-лист деплоя на чистый VPS — [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Фаза 2 — удержание и рост

### 2.1 Реферальная программа
В `db/models.py` уже есть `User.referred_by_id`, `User.balance`, `ReferralMode` enum.
Нужно:
- Таблица/настройка глобального режима рефералки: `off` / `days` / `revenue_share`
  (простая таблица `Settings(key, value)` или отдельная модель `ReferralConfig` —
  на твоё усмотрение, но должно настраиваться без правки кода)
- В `bot/services/delivery.py` уже есть заготовка `_reward_referrer()` — реализовать:
  - режим `days`: и пригласивший, и приглашённый получают N дней (значение N — настраиваемое)
    при **первой** успешной оплате приглашённого (сейчас в коде уже проверяется, что это
    первый оплаченный заказ — используй эту проверку)
  - режим `revenue_share`: пригласившему на `User.balance` зачисляется % от суммы заказа
    приглашённого (при каждой оплате, не только первой)
- Команда `/referral` в боте — показывает реферальную ссылку (`https://t.me/<bot>?start=<telegram_id>`),
  статистику приглашённых, баланс
- Если добавляешь revenue-share — нужен способ вывести/потратить баланс (например,
  оплата подписки с баланса как отдельный "способ оплаты" в `payments/`)

### 2.2 Умные рассылки (триггерные уведомления)
Референс: событие "за N дней ДО окончания подписки" → отправить шаблон сообщения,
таргетинг по тарифам.
- Новая модель `BroadcastRule`: `event_type` (`before_expiry` / `after_expiry`), `value` (число),
  `unit` (`days`/`hours`), `message_template` (текст), `target_tariff_ids` (nullable = все), `is_active`
- Фоновая задача (APScheduler или простой `asyncio` цикл с периодической проверкой раз в час):
  находит пользователей, чей `expire` в Marzban попадает в нужное окно, и кому это правило ещё
  не отправлялось (нужна таблица `BroadcastLog(rule_id, user_id, sent_at)`, чтобы не спамить повторно)
- Админ-команды для управления правилами — можно просто через Telegram-команды с админ-проверкой
  (без веб-панели пока, веб-панель — отдельная большая задача вне этого бота)

### 2.3 Тикет-система поддержки
Модели `SupportTicket`/`TicketMessage` уже есть в `db/models.py`.
- `/support <текст>` — создаёт тикет со статусом `open`, первое сообщение = текст команды
- Дальнейшие сообщения пользователя в личке бота (если у него есть открытый тикет) —
  добавляются в `TicketMessage`
- Уведомление в админ-чат (ID из `.env`) о новом тикете/сообщении
- Админ отвечает через бота (например reply на пересланное сообщение, либо команда
  `/reply <ticket_id> <текст>`) — сообщение уходит клиенту и сохраняется как `is_from_operator=True`
- Команда `/close_ticket <id>` для админа

## Фаза 3 — Advanced/Pro

### 3.1 Детект аномального потребления трафика
Формула: `Score = (всего трафика / дней с момента сброса) / лимит устройств`.
- Периодическая задача (раз в сутки): тянет `used_traffic` из Marzban через
  `marzban_client.client.MarzbanClient` для всех активных пользователей, считает Score,
  сохраняет топ-N в таблицу `AnomalyScore(user_id, score, calculated_at)`
- Админ-команда `/anomalies` — показывает топ пользователей по Score за последний расчёт
- Порог и действие (просто уведомление / автобан) — сделай настраиваемым, не хардкодь

### 3.2 Динамические акции и скидки
- Модель `PromoEvent`: `name`, `discount_percent`, `applies_to_tariff_ids` (nullable = все),
  `trigger` (`manual` / `on_churn` — срабатывает автоматически при истечении подписки),
  `is_active`
- В `bot/handlers/tariffs.py` при показе тарифов — применять активную скидку к цене, если есть
- Для `on_churn`: та же фоновая задача, что и умные рассылки, может присылать
  персональное предложение со скидкой пользователям, у которых подписка истекла N часов назад

### 3.3 Встроенный редактор конфигов Xray
Это надстройка над Marzban core-config API (`/api/core/config` GET/PUT в Marzban) —
не реализовывать свой Xray-парсер, использовать существующий эндпоинт Marzban.
Эта часть скорее для будущей веб-панели, чем для Telegram-бота — если приоритет невысокий,
можно отложить в самый конец.

### 3.4 Мониторинг микросервисов и автовосстановление
- Простой healthcheck-цикл: бот раз в N минут пингует сам себя (жив ли polling), проверяет
  доступность Marzban (`GET /api/system`), проверяет доступность БД
- При падении Marzban — уведомление в админ-чат, НЕ пытаться "автовосстанавливать" сам Xray —
  это забота инфраструктуры/Marzban, а не бота
- Дашборд-команда `/status` для админа — сводка по всем чекам
